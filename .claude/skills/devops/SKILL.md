# DevOps: lessons

## Environments

- Commit the environment and access doc (hosts, how to reach them, which credentials exist where) and every helper script on day 1. Why: orchestrator scripts kept in `/tmp` and a 127 KB spec in a session scratchpad were lost or found only by chance. Source: pesitro retro 2026-10-21.
- Give every parallel worktree its own environment (port = base + ticket number) and keep heavy shared environments out of the ticket tier. Why: one shared environment slot queued tickets for 7–16 h while implementing took 50–90 min. Source: pesitro#236, retro 2026-10-21.
- Keep one copy of the repo per purpose; delete stale clones. Why: a stale Windows clone misled 12 sessions. Source: pesitro retro 2026-10-21.
- Set agents up with key-based SSH to staging before the first deploy. Why: password prompts across 10+ terminal tabs blocked every staging step. Source: pesitro retro 2026-10-21.
- Keep staging and production configuration as idempotent scripts or migrations, not runbook clicks. Why: manual config drifted from the seed, and a staging script rewrote page content. Source: pesitro verification review 2026-10-21.
- Pull MinIO as `cgr.dev/chainguard/minio:latest`. Why: MinIO stopped publishing community images; `minio/minio` no longer exists on Docker Hub and quay.io returns 401. Source: Servisnik#60.
- Start an optional Compose service with `docker compose --profile <p> up <service>` and stop it with `docker compose --profile <p> down`, never with `compose run`. Why: `down`, even with `--remove-orphans`, leaves `run` containers and services of inactive profiles running, and a tunnel outlived `down`. Source: Servisnik#60.
- When npm or pnpm fails TLS (`UNABLE_TO_VERIFY_LEAF_SIGNATURE`, `UnknownIssuer`), read the issuer first with `openssl s_client -connect registry.npmjs.org:443`. A TLS-inspecting firewall's CA goes into `NODE_EXTRA_CA_CERTS`; without that CA, pnpm installs through `registry.yarnpkg.com` in two steps: `--lockfile-only`, strip the lockfile's `tarball:` URLs, then `--frozen-lockfile`, each with `--registry`. Why: a FortiGate intercepted only registry.npmjs.org, `--use-system-ca` failed because Windows did not trust its CA either, and a one-step mirror install failed because the mirror's metadata keeps npmjs tarball URLs. Source: Servisnik#44.
- Ship a PostgreSQL enum value (`ALTER TYPE … ADD VALUE`) in a migration that nothing in the same deploy uses; the first default, CHECK, index or UPDATE that uses it goes in a later deploy. Why: drizzle's migrator applies all pending migrations in one transaction, and PostgreSQL refuses a new enum value used in the transaction that added it ("unsafe use of new value"). Source: Servisnik#98.
- When parallel branches cut from one integration branch each add the next migration number, the branch merged second merges the integration tip, deletes its migration and regenerates it (`drizzle-kit generate`) in a plain commit, so it gets the next number, a `when` later than its new predecessor and that predecessor as snapshot `prevId`. Why: three tickets of one run each created migration 0008, and a hand-renamed migration kept an earlier `when`, which the migrator skips on a database that already ran the newer one. Source: Servisnik#121, #122, #123, #96.
- After renumbering a migration to resolve a merge, reset every local and test database that ran the old number. Why: drizzle skips a migration whose timestamp is older than the last one applied, so a database migrated before the renumbering silently missed the other branch's migration. Source: Servisnik#98.
- Take every timestamp of a column from one clock: when the insert default is the database's `now()`, the ORM's update hook writes `now()` too, never the app's `new Date()`. Why: a Docker database clock ran ahead of the host, so a replaced logo got an older `updated_at` and its cache-buster went backwards. Source: Servisnik run 2026-10-28 (#122).
- In an image, install a headless browser's system libraries from an explicit apt list, never `playwright install --with-deps`. Why: `--with-deps` always adds Playwright's `tools` group (xvfb, CJK, emoji and unifont fonts), which tripled an app image to 1.37 GB against a 500 MiB registry and made Chromium pick a CJK font. Source: Servisnik#100.

## CI and deploy

- Deploy only a tree whose exact hash passed CI: the merged default-branch commit, read with `git log origin/<default> -1` after a fetch. A production deploy asks for a typed confirm string. Wrap the deploy in maintenance mode, check the installed version, smoke-test HTTP 200 on key URLs, and diff the error log for new fatals. Source: pesitro `deploy.yml`, elsteo `DEPLOY.md`.
- Validate a reverse-proxy config with the server's own validator (`caddy validate`, `nginx -t`) on the target box or a scratch copy before proposing it, above all a multi-host config. Source: elsteo CLAUDE.md.
- A script that generates a secret confirms it is saved in the password manager before it overwrites or deletes anything, and never prints it. Source: elsteo CLAUDE.md.
- Budget CI from day 1: artifact retention in days, the full suite once per integration batch, and minutes tracked. Why: the artifact quota caused a 3-day CI and deploy outage, then minutes ran out. Source: pesitro#133, #224.
- Run dependency audit and secret scanning in CI. Source: pesitro verification review 2026-10-21.
- Schedule a heartbeat for background jobs (cron, queues) that alerts when the last run is too old. Source: pesitro verification review 2026-10-21.
- Wire the edit tier as a script that runs only for source files inside the repo and exits 2 with the install command when its tool is missing, and pipe-test it with payloads built by `JSON.stringify`. Why: a bare `pnpm typecheck` hook fired on every Edit in the session, including files of another repo, and blocked each one with "pnpm: command not found" on a machine without pnpm. Source: Servisnik#85.
- Give every setup step in the README a root script and have CI run that same script. Why: in a pnpm workspace the README's `pnpm exec playwright install chromium` failed from the repo root because the bin lives only in `apps/web`, and nothing ever ran the README as written. Source: Servisnik#78.
- Give the database client a connect timeout shorter than the platform's health-check timeout, and test the health route against an unroutable host, not only a refused port. Why: `pg.Pool` has no connect timeout by default, so `/api/health` hung instead of returning 503 when the host dropped packets. Source: Servisnik#78.
- Run deploy jobs only from the default branch, through a GitHub Environment restricted to it that holds the deploy secrets. Why: a `workflow_dispatch` deploy ran on any ref, repo-level secrets were readable by every branch's CI in a public repo, and a branch could carry its own copy of the CI gate. Source: Servisnik#83.
- Give every GitHub Actions `run:` step that pipes `shell: bash`, and have tests that execute workflow steps run them with `bash -eo pipefail` like the runner. Why: the default `bash -e {0}` has no pipefail, so a failing `list-tags | tool | xargs --no-run-if-empty` stayed green with registry retention silently off. Source: Servisnik#89.
- Registry retention protects the live tag by name (read from the platform, not "newest N") and also runs after a failed deploy once the push succeeded. Why: retention that ran only after a successful deploy let a streak of failed first-setup deploys fill the 500 MiB registry, so the push that would trigger cleanup failed. Source: Servisnik#89.
- Verify a managed database's TLS chain with the CA the provider binds (DigitalOcean `${db.CA_CERT}`) instead of turning verification off. Why: the first deploy spec used `uselibpqcompat=true`, which keeps TLS but trusts any certificate. Source: Servisnik#83.
- In an image that runs TypeScript with Node's type stripping, install the filtered workspace (`pnpm install --prod --filter "<app>..."`) instead of `pnpm deploy`, and re-run the image's scripts after every new workspace dependency. Why: `pnpm deploy` copied `@servisnik/domain` into `node_modules`, where Node refuses to strip types, so migrate and seed in the image failed while the app itself still started. Source: Servisnik#83.
- When a change stops a seed, deploy step or env variable from resetting a credential, document the replacement break-glass in the same PR. Why: the deploy seed stopped resetting the admin password, and that reset was the only way back in for a sole admin who forgot it. Source: Servisnik#140.

## Agent guardrails

- Block in-place shell edits with a `PreToolUse` hook on Bash that exits 2 on `sed -i`, `perl -i` and heredocs redirected into files, and edit with the Edit and Write tools. Why: shell edits halved the backslashes in a deploy script and a hook, and broke line continuations. Source: elsteo `.claude/settings.json`.
- Hard-block destructive commands against production hosts in a `PreToolUse` hook with its own `--test` cases: volume deletion (`compose down -v`, `volume prune`), destructive SQL on money tables, database shells without read-only mode, reading `.env` values (key names only: `cut -d= -f1`), pushing a licensed image, test toggles on production. Source: elsteo `.claude/hooks/server-guard.js`.
- Write a file that must keep `\uXXXX` escapes as text (a regex or SQL listing combining marks or invisible spaces) with a script that builds the backslash (`String.fromCharCode(92)`), not with the Edit or Write tool, and check the bytes with `od -c`. Why: the tool input is JSON, so the escape arrived as the character itself and a migration got invisible characters. Source: Servisnik#71.
- Tell the human to paste secrets into a terminal, never into chat; a secret that lands in chat is flagged for rotation at once. Source: elsteo CLAUDE.md.
- To commit in a git worktree, `cd` into it in a Bash call of its own before the commit, and reach other repos with `git -C <path>`, never `cd`. Why: the guardrail hook that blocks commits on `main` reads the session's working directory, which a `cd` earlier in the same command has not moved yet, so a commit on the run's integration branch was blocked while the main checkout sat on `main`; a later `cd` into another repo reset the session back to it. Source: Servisnik run 2026-10-28.

## Unattended runs

- Before a night run, the human grants authority in chat, time-boxed and in their own words ("merge into the integration branch tonight, ask only business questions"), and the harness has matching allow rules. Why: authority written in a prompt file was refused, and a merge denial idled the queue for 5.5 h. Source: pesitro retro 2026-10-21.
- Issue each allow-listed external write (`gh issue close`, `gh pr merge`) as its own bare Bash call, with no pipe, `&&`, `;` or redirection. Why: a 504 hit the second close in an `&&` chain after the first had applied. The piped retry was then denied by auto mode as "External System Writes" although `Bash(gh issue close *)` was allowed, and the bare call passed. Source: Servisnik#29.
- Write only to issues that the brief or the user names. A note for another session's ticket goes on a ticket you own, or to the user. Why: auto mode denied a bare `gh issue comment --body-file` on a review ticket the brief never named ("External System Writes"), while the same call on a ticket the coordinator had named passed. The form was not the cause, so a retried variant cannot pass. Source: Servisnik#54.
- Before a ticket where the agent opens a public tunnel (cloudflared, ngrok), the human adds a Bash allow rule for that exact command. Why: Claude Code auto mode denies it as "External Ingress Tunnel", and a yes in chat covered one run only. Source: Servisnik#60.
- Check that auth tokens outlive the run, and run a watchdog that notifies when the run stalls. Why: an expired OAuth token left the queue dead for 2 h 40 min, and a stalled stream for about 8 h, both silently. Source: pesitro retro 2026-10-21.
- Run only as many implementers at once as the host carries: before starting another, read the CPU load (Windows: `(Get-CimInstance Win32_Processor | Measure-Object LoadPercentage -Average).Average`; elsewhere the load average) and start it only while the load stays under about 80 %, counting every Playwright and Testcontainers run and what else the human runs on the machine. Why: a run kept up to 8 implementers going and the CPU at 100 % for hours, so tickets took 1.5–2.5 h instead of under one, e2e needed fewer workers and reruns, and load timeouts and a deadlock turned verify red at random. Source: Servisnik run 2026-10-28 (Kazarr).
- The coordinating session reads no code; children report in ten lines or fewer. Why: 102 child notifications (~70k tokens) and two compactions filled the orchestrator. Source: pesitro retro 2026-10-21.
- When a ticket branch must be rewritten, push the result under a new branch name and merge that one; never plan on a force-push. Why: auto mode denied the force-push of a rewritten ticket branch, and the coordinator must not repeat a denied action for the implementer. Source: Servisnik#83.
